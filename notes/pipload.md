### Overlap With stamp

1. **Version discovery and loading are delegated, not a separate current version engine.** `pip_read` normalizes or checks the extension, calls `stamp::st_versions`, adds a relative `vintage` column only for `version = "available"`, and passes the version selector to `stamp::st_load`. It does not implement negative-index or specific-version resolution itself (`P:R/pip_read-write.R:63-96,106-107`). Test source asserts latest, previous, available, and explicit-ID reads (`P:tests/testthat/test-pip_read-write.R:46-90,165-174`). These tests were not run.
2. **Saving and provenance are delegated.** `pip_write` adds an extension when absent and forwards `x`, file, format, alias, custom metadata, code, primary key, verbosity, and `...` to `stamp::st_save`. The wrapper returns stamp's result invisibly. It contains no separate content-hash calculation or parent-graph decision in this function (`P:R/pip_read-write.R:151-187`). Test source passes a function and `metadata = list(foo = "bar")` and checks that metadata/code-hash field names exist; it does not check custom-field values or metadata-only updates (`P:tests/testthat/test-pip_read-write.R:115-138`). Exact hash, parent, staleness, and early-cutoff behavior are stamp-side UNKNOWN here.
3. **There is legacy overlap outside stamp.** The older `pip_load_aux` scans a PIP `_vintage` directory, sorts timestamped files, selects a previous or named vintage, reads it directly, and sets a `version` attribute (`P:R/OLD_pip_load_aux.R:141-213,233-282,292-320`). Legacy inventory updating hashes country path lists with `xxhash64`, compares signatures, skips an unchanged inventory unless forced, and writes current/vintage inventory and signature files directly (`P:R/pip_update_inventory.R:99-128,178-194,290-322,332-355`). This is directory-inventory change detection, not evidence of survey-content invalidation or artifact lineage. The inventory test calls the update path, but is not a hash or cascade test (`P:tests/testthat/test-pip_inventory.R:1-15`).

### Limits That Affect the Role

- **Separate metadata artifact, not a generic sidecar reader.** Inventory enrichment constructs `path_metadata/versions/version_id_metadata/artifact` and calls `qs2::qs_read` directly. It bypasses stamp resolution and depends on this storage layout. It must not be treated as proof that pipload reads stamp custom sidecar fields (`P:R/pip_inv_enrich.R:219-260`). Its tests construct that layout themselves (`P:tests/testthat/test-pip_inv_enrich.R:3-14`). Compatibility with stamp HEAD is UNKNOWN pending cross-check.
- **Not proof of immutable release membership.** The inspected release-inventory loader accepts a caller-supplied version, otherwise defaults to NULL, and delegates the read; it does not itself define a named set of artifact versions (`P:R/load_pip_data.R:276-300`). A release-name helper assembles date, PPP, and purpose fields, but its test file starts with `skip("this function is not working right now")` (`P:R/pip_create_vintage.R:33,333-366`; `P:tests/testthat/test-pip_create_vintage.R:1`). A name is not proof of the Decided release-version contract (`D:SYSTEM_DESIGN.md:236`). A complete release contract is UNKNOWN in this L1 collection.
- **Format interfaces need a cross-check before use for fst.** The PIP ID checker forces a `.qs2` extension, while `pip_read` rejects a mismatch with an explicitly requested format. `load_aux_data` constructs a path using its `format` argument but does not forward that argument to `pip_read`, whose default is `qs2` (`P:R/load_pip_data.R:84-85,139-144,375-389`; `P:R/load_aux_data.R:37,61-66`; `P:R/pip_read-write.R:48-53,63-79`). Thus these source paths do not establish reliable explicit fst access. Generic wrapper test source covers qs2 and rds, not these PIP loaders with fst (`P:tests/testthat/test-pip_read-write.R:176-199`). Runtime outcome is UNKNOWN.
- **DLW discovery is not established as a working storage query.** `find_dlw_data` resolves `dlw_data`, but then lists `pip_data`; its constructed year column is `surveyid_year`, whereas later latest-year/version groups refer to `Year` (`P:R/load_dlw_data.R:175-205,210-230`). Do not classify this path as verified current DLW discovery. Execution and intended fallback are UNKNOWN.

### Suggested Role: Proposal Only

Keep pipload as the **PIP-aware storage access adapter**: resolve folders and artifact names, apply survey/inventory queries, and expand PIP metadata. Keep stamp as the storage/version/provenance mechanism. Treat `pip_read` and `pip_write` as delegates, not a competing planner. Do not use legacy inventory signatures to decide estimation rebuilds. This is a proposal, not an applied design change (`P:R/load_pip_data.R:174-255,276-300`; `P:R/pip_inv_enrich.R:180-260,290-331`; `P:R/pip_read-write.R:82-107,175-185`; `P:R/pip_update_inventory.R:178-194,345-355`; `D:SYSTEM_DESIGN.md:188-194,286`).

The load-then-deflate wrapper and legacy module preference show that today's package boundary is wider than this proposed adapter role. Decide their future location separately; the deflation wrapper only calls pipdata and does not contradict pipdata's Decided ownership of deflation (`P:R/load_pip_deflated_data.R:165-172`; `P:R/pip_find_data.R:399-419`; `D:SYSTEM_DESIGN.md:153-154,282,286`). No ownership change is authorized by this note (`D:SYSTEM_DESIGN.md:16-18`).
